# Qdigo code and content audit (2026-10-05)

A read-only review of the whole repo, split across parallel agents: the web app, the server and Docker, the shared packages (`schema`, `sdk`, `cli`), and all 11 content modules. The top findings were spot-checked against the source before this report was written. Nothing was changed during the audit.

**Baseline at audit time:**
- `pnpm typecheck` is clean.
- `pnpm build` succeeds.
- `pnpm kodigo validate modules` passes all 11 modules, with one lint warning type.
- `pnpm test`: 67/68 pass. The failing test is a timeout, see S10.

## Summary

| Area | Verdict |
|---|---|
| Content correctness | No hand-written answer key is wrong. Every lecture example matches its `logic.js`. All 107 static answer keys and most worked examples were rechecked by hand. |
| Grading | Number parsing marks some correct answers wrong and some wrong answers right. **Students see this.** |
| Question generators | 4 generators sometimes produce unsolvable or contradictory questions. **Students see this.** |
| Security | Module code is treated as trusted. The sandboxes on the server, in the CLI and in the browser can all be escaped. This matters if you import modules you didn't write. |
| Robustness | Race conditions on files and IndexedDB, unvalidated request input, and promises nobody catches. |
| Code quality | Generally careful and well organised: no `eval`, deterministic seeds, constant-time token comparison, non-root container. |

**Recommended order:** G1–G3, then C1–C4, then S10 (the flaky test), then security S1–S5 before importing any third-party module.

## 1. Grading bugs (students see these)

### G1. A number in parentheses is graded as negative
[quiz.ts:291](../packages/schema/src/quiz.ts:291). The accounting rule "(1,200) means −1,200" applies to every numeric question.
- `(2/3)` parses as −0.667 and `(0.5)` as −0.5, so a correct answer is marked wrong. Reproduced.
- In journal entries ([journal.ts:121,151](../packages/schema/src/journal.ts:121)), `(500)` typed in the Debit column nets to a 500 credit, so an entry in the wrong column is graded correct.

**Fix:** only treat parentheses as negative for money and journal fields, and make the Debit and Credit columns reject negatives.

### G2. Other number-parsing slips
All in `parseNumber` / `checkNumeric`, [quiz.ts:285-300](../packages/schema/src/quiz.ts:285). Each was reproduced except the tolerance one.
- Every comma is deleted, so `2,5` becomes 25. It should be rejected as unreadable.
- A lone `%` parses as 0, so it is graded correct whenever the answer is 0.
- `accept: ['percent']` doesn't stop a plain decimal like `0.5` from being accepted.
- The default tolerance is an absolute 0.01 ([quiz.ts:89](../packages/schema/src/quiz.ts:89)). For an answer of 0.004, typing `0` passes. It should be relative for small values.
- `checkMulti([0,0],[0,1])` returns full credit ([quiz.ts:337](../packages/schema/src/quiz.ts:337)). This only matters if the UI can send duplicates.

### G3. Exam attempts are saved twice in dev mode
[QuizRunner.tsx:107](../apps/web/src/quiz/QuizRunner.tsx:107). `record()` runs inside a `setSlots` updater, and StrictMode runs updaters twice in dev. Mastery and the review schedule are updated twice. Production builds aren't affected, but side effects shouldn't live in updaters.

**Fix:** grade first, then call `record()` outside the updater.

## 2. Broken question generators (students see these)

### C1. abc `plantQ`: contradictory machine-hour pools
[abc/logic.js:362](../modules/abc/logic.js:362). `randomPools` can pick "Machining" as pool 0 or 1 while pool 2 is overwritten as "Other overhead (machine hours)". The question then shows two machine-hour pools whose numbers disagree. Found in 107 of 300 seeds. Affects `plant-numeric` and `plant-handcalc`.

**Fix:** leave Machining out of the sample.

### C2. process-costing `fifo-handcalc`: can't be solved
[process-costing/logic.js:443](../modules/process-costing/logic.js:443) with [quiz.yaml:367](../modules/process-costing/quiz.yaml:367). About half the time materials are added at the end, but the prompt never says so. Without that, materials equivalent units can't be worked out.

**Fix:** add the materials timing text to the prompt, as `tiQ` does.

### C3. time-series `pacfQ`: impossible autocorrelations
[time-series/logic.js:820](../modules/time-series/logic.js:820). r1 and r2 are drawn independently. About 10 of the 63 pairs give |φ₂₂| > 1, e.g. r1 = 0.9 and r2 = 0.1 gives −3.74.

**Fix:** only accept pairs where `r2 >= 2*r1*r1 - 1`.

### C4. time-series seasonal naive: formula wrong past one season
[time-series/glossary.yaml:83](../modules/time-series/glossary.yaml:83). ŷ = y_{t+h−m} only holds for h ≤ m, but the quiz uses h up to 30. The general form is y_{t+h−m(⌊(h−1)/m⌋+1)}.

## 4. Security

The threat model: only an admin can import modules, but the `kodigo validate` / `pack` / `unbundle` commands take any zip or LLM-pasted bundle. Each item below matters as soon as a module's author isn't fully trusted.

### S1. The `node:vm` sandbox can be escaped (critical)
[node.ts:171,201](../packages/schema/src/node.ts:171). Host objects (the `console` no-ops, `sdk`, `rng`) are passed into the context, so their `.constructor` is the host's `Function`. Reproduced: `console.log.constructor('return process')()` returned the real `process`. That means any logic.js run by the CLI or the server's import validation can run any code on the host.

**Fix:** run logic in a worker or child process with `--experimental-permission`, or in `isolated-vm`. `vm` is not a security boundary.

### S2. The vm timeout doesn't cover async code
[node.ts:176-205](../packages/schema/src/node.ts:176). `Promise.resolve().then(() => { for(;;); })` hangs the event loop forever. `microtaskMode: 'afterEvaluate'` isn't set. Not reproduced.

### S3. Module code can change the shared `sdk`
The real `sdk` object is passed in without being frozen. `sdk.round = () => 0` corrupts every module validated after it in the same process.

### S4. The browser worker sandbox can be escaped
[logic.worker.ts:10](../apps/web/src/modules/logic.worker.ts:10). The worker only sets `fetch`, `indexedDB` and the like to undefined on `self`. A nested `new Worker(blob:)` gets them back, and the CSP allows `worker-src blob:`. Scenario: while an admin previews an import, the module reads the admin token from IndexedDB and POSTs it to `/api/modules`. In Vite dev there is no CSP at all.

**Fix:** run module logic in a sandboxed cross-origin iframe, or keep the admin token out of the origin's IndexedDB.

### S5. Path traversal and zip bombs on import
- `normalizePath` ([bundle.ts:296](../packages/schema/src/bundle.ts:296)) strips `./` and a leading `/`, but never rejects `..`.
- `kodigo unbundle` ([cli/src/index.ts:97](../packages/cli/src/index.ts:97)) can therefore write `<<<FILE ../../../.bashrc>>>` outside the output folder.
- `readZip` keeps `..` names the same way.
- The server's install path strips leading `../` and looks safe.
- There's no limit on unzipped size or entry count (bundle.ts:93-111), so a small zip can exhaust server memory.

### S6. SVG files from modules can run script on the app's origin
[apps/server/src/index.ts:58,80-94](../apps/server/src/index.ts:58). Module files are served same-origin, and the CSP header is only added to `text/html`. Blob SVG URLs made in `store.tsx:49` are never revoked either.

**Fix:** send CSP plus `Content-Disposition: attachment` for SVG, or serve module files from a separate origin.

### S7. The admin token defaults to `dev`
[index.ts:21](../apps/server/src/index.ts:21). This applies whenever `NODE_ENV` isn't `production`, so `node dist/index.js` on a host without the variable leaves admin open. Docker sets `NODE_ENV` correctly. Token guesses aren't rate-limited.

### S8. `PATCH /api/modules/__proto__` corrupts every object on the server
`builtin['__proto__']` counts as found, so `enabled` and `course` are written onto `Object.prototype` ([registry.ts:204](../apps/server/src/registry.ts:204)). Admin-only. The `when` expression parser has the same `in` pattern ([expr.ts:75](../packages/schema/src/expr.ts:75)), but no exploit was found there. Use `Object.hasOwn`.

## 5. Server robustness

## 7. Shared packages: minor issues

**`when` expressions** ([expr.ts](../packages/schema/src/expr.ts)):
- `==` and `!=` subtract their operands, so `x/0 == x/0` and `x/0 != x/0` are both false.
- `missing == null` is false.
- Deep nesting throws `RangeError` outside the `try` (:148), and that error reaches render in IntuitionTab.tsx:150. The validator catches it for validated modules.
- The parse cache is unbounded.

**Schema** ([schemas.ts](../packages/schema/src/schemas.ts)):
- A code-fill blank with neither `accept` nor `regex` can never be answered.
- `when` allows an empty string.
- Author regexes in `checkBlank` are unanchored, which is a ReDoS risk.

**RNG** ([sdk/src/index.ts:192](../packages/sdk/src/index.ts:192)):
- Seed 0 and seed 0x9e3779b9 give the same sequence.
- Fractional seeds are truncated.
- `int(lo, hi)` with `hi < lo` returns values outside the range.

## 8. Test coverage gaps

**`packages/schema/test` has no tests for:**
- **Sandbox:** vm escape, async hangs, `sdk` mutation.
- **Bundles and zips:** path traversal in `parseBundle` / `readZip`.
- **Number parsing:** `parseNumber` edge cases (parentheses, commas, `%`, `accept`).
- **`when` expressions:** Infinity/NaN, null/undefined, deep nesting, function names that exist on the prototype.
- **Answer checking:** duplicates in `checkMulti`, and `checkOrder` input that isn't a permutation.

**The module validator does not check:**
- `lessonRef` targets (T8 slipped through).
- Whether generated numbers are mathematically possible (C3).
